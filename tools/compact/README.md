# 保锚压缩

长会话会撞上下文墙。常见做法是让模型总结旧对话——**摘要会漂移，而且数字和路径恰好是第一样被改写掉的东西**。

这个工具不这么干：它只**整段删除**，从不改写任何一句；凡带「必须原样保留的字面量」（路径、URL、标识符、引号里的字符串）的段落一律保留。压缩完再验证一遍——**不是假设没丢，是检查过没丢**。

```bash
node tools/compact/cli.mjs transcript.md --budget 120
```

```
单元 10 → 6（去掉 4）
tokens 295 → 139（省 156，53%）
必须原样保留的字面量 2 个，缺失 0 个
叙述性数字 8 个，压缩时去掉了 5 个
✓ 没有一个可执行的字面量被丢掉
```

## 三级保留

| 级别 | 条件 | 会被删吗 |
| --- | --- | --- |
| **must** | 含路径 / URL / 标识符 / 引号字符串，或是一句“决定” | 永不 |
| **tail** | 最后 N 段（默认 2），这里放着当前状态 | 永不 |
| **numbers** | 只有叙述性数字（“当时并发只有 50”） | 预算不够时，先删散文再删它 |
| **prose** | 纯叙述 | 最先删 |

**为什么数字是二等公民**：`并发只有 50` 是背景，删了不影响执行；`/var/spool/upload` 删了代码就跑不起来。混为一谈会让压缩几乎压不动——第一版就是这样，10 段只能删 1 段。

## 不做的事

- **不生成摘要**。一旦让模型总结，误差会像多步执行一样复利（95% × 20 = 36%）。
- **不改写任何一句**。删或留，没有中间态，所以没有改写带来的漂移。
- **不碰语义判断**。哪些是“决定”靠标记词识别，识别不了就按散文处理——宁可多留一段。

## 退出码

`0` 没有丢失必须保留的字面量；`1` 丢失了（说明实现有 bug，应该当测试失败看）。

## 限制

- 只按段落切分，不按句子。一段里既有决定又有废话时，整段保留。
- “决定”靠关键词（决定 / 改成 / 不改 / 必须 / 禁止…），措辞少见时会漏。
- 不处理多模态内容和 tool call 记录。
