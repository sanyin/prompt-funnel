# Claude Code 接入（`UserPromptSubmit` hook）

Claude Code 是目前唯一提供**公开、稳定的「发送前」钩子**的宿主，所以这里能做出最接近原始设想的效果：你的话发出去之前，先被收束，再决定发不发。

## 装

最省事的是全局装一次（避免每次 `npx` 冷启动）：

```bash
npm i -g prompt-funnel
```

然后在 `~/.claude/settings.json` 里加：

```json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          { "type": "command", "command": "funnel hook", "timeout": 10 }
        ]
      }
    ]
  }
}
```

没装全局的话，把 `command` 换成 `npx -y prompt-funnel hook`（首次会慢一点）。

## 三种模式

| 模式 | 行为 | 怎么开 |
| --- | --- | --- |
| `advisory`（默认） | 请求模糊时，把收束后的结构作为上下文附加进这一轮；请求清晰时**完全静默** | 默认 |
| `block` | 请求模糊时**拒绝发送**，并把建议的写法给你 | `command: "funnel hook --mode block"` |
| `off` | 完全不介入 | `command: "funnel hook --mode off"`，或删掉这一段 |

也可以用环境变量统一控制：`FUNNEL_HOOK_MODE=block`。

## 怎么确认它在工作

随便输一句模糊的：

> 帮我写个爬虫，顺便加个代理池，再做个面板

如果钩子生效，模型看到的上下文里会多出一段「目标 / 要求 / 交付 / 完成标准 / 待确认」。

清晰的提问（例如「这段代码为什么报 TypeError」）不应该有任何附加内容——**这是设计目标**，不是没生效。

## 为什么默认不做成拦截

拦截意味着用户的话被挡回去。写提示词时被挡三次，人的反应是去找开关，而不是改用法。所以默认是「附加结构、不拦人」；真正需要强制的场景（比如给团队统一规范）再开 `block`。

## 已知限制

- 钩子是**无状态**的：它只看到这一条 prompt，看不到上文。所以追问（「继续」「再改第 2 点」）应当放行——`gate` 会把它们判定为追问并静默通过。跨轮修改请用 `funnel refine`。
- 每次触发会启动一个 Node 进程（约 40–60ms）。`gate` 本身是微秒级的，开销主要在启动。
- 钩子的输出格式按 Claude Code 公开文档实现，并在本地用模拟 payload 验证过；不同版本若改了字段，最坏情况是钩子静默失效（它会吞掉所有异常并退出 0），不会卡住你的会话。
