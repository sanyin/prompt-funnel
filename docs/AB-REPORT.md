# 真实模型 A/B：收束前 vs 收束后

这是 [EVAL.md](./EVAL.md) 里说「没测」的那部分。现在测了，结论分两半：**能证明的和不能证明的**。

## 方法

- 模型：`deepseek-chat`，temperature 0.7，`max_tokens` 900
- 用例：`evals/dataset.json` 里被判为需要收束的 10 条
- 分组：`raw`（用户原话直接发）vs `compiled`（收束后的提示词）
- 采样：每组每用例 3 次，共 60 次调用
- 复现：`FUNNEL_API_KEY=... node evals/live.mjs --model deepseek-chat --samples 3`

原始输出在同目录的 `evals/live/<model>-<时间戳>/`（未提交，`.gitignore` 已忽略）。

## 结果

| 指标 | 原文直发 | 收束后 | 说明 |
| --- | --- | --- | --- |
| 关键内容命中率 | 97% | 100% | 差异只是 1 次采样，**不构成结论** |
| 平均响应长度（字符） | 1669 | 1587 | 略短，不是「更长=更详细」 |
| 平均延迟（ms） | 268 | 182 | 噪声，与提示词无关 |
| 输入 tokens | 18 | 276 | 真实成本：每条多约 258 tokens |
| **明确说出自己的假设** | **5/30** | **18/30** | 见下 |
| **带自检/验收表述** | **2/30** | **17/30** | 见「混杂因素」 |

### 最有价值的一条

不是命中率，也不是长度，而是**模型开始承认自己做了假设**。

同一个用例（「帮我写个爬虫，同时加上代理池，另外再做一个可视化面板」），两次回答的开头：

**原文直发**：

> # 完整爬虫 + 代理池 + 可视化面板方案
> 下面给你一套**可直接运行**的完整方案，包含三个模块……

**收束后**：

> # 爬虫 + 代理池 + 可视化面板 完整实现
> 由于你未指定目标网站，我采用 **Python 技术栈**，以 `https://httpbin.org/ip` 作为**示例目标**（可验证代理是否生效），你可以替换成任意目标站点。

区别不在有没有给出方案，而在**有没有把「我替你决定了什么」说出来**。前者拿到一份 3000 字的实现，得自己去找哪里是猜的；后者第一句就交代了技术栈是选的、目标是占位的。

这正是收束时把「未确认条目 → 默认假设 → 若不符的后果」写进提示词的直接结果。

## 混杂因素（必须说清楚）

「明确说出假设」和「带自检表述」这两个指标是**关键词匹配**，而收束后的提示词里本来就含有「假定」「完成标准」这些词——模型可能只是在复述模板，而不是真的想过了。

所以这两个数字应当这样读：

- 5/30 → 18/30 **不能**当成「假设意识提升 3.6 倍」；
- 它**能**说明的是：收束后的提示词让模型进入了「先交代前提再动手」的模式，而且上面那段人工对照里，交代的内容是**实质性**的（技术栈、目标站点），不是无意义的复读。

要排除混杂，得做盲评：`rating.csv` 就是为此准备的，A/B 顺序已打乱、臂别藏在最后两列。那份表还没人评——这是这个实验唯一没做完的部分。

## 不能证明什么

1. **不能证明答案更好**。样本 10 个用例 × 3 次，且只测了一个模型。没做人工盲评前，任何「提升 X%」的写法都是编的。
2. **不能证明对所有场景有效**。评测只覆盖了「被判为需要收束」的用例；单点提问根本不会进入收束流程，它们的表现应当**没有区别**——这一点从闸门设计上是成立的，但这次没测。
3. **成本是确定的**：每条被收束的请求多约 258 输入 tokens。值不值取决于上一条。
