# 成本

「18 → 264 tokens」这个数字会吓人，但它主要是**分母太小**造成的。这份文档给的是绝对开销和可选档位。

## 实测（16 条用例，中位数）

| 排版 | 中位 tokens | 相对原文的绝对开销 |
| --- | --- | --- |
| 原文 | 18 | — |
| `bluf` + 附原文（默认） | 263 | **+245** |
| `bluf` | 228 | +210 |
| `compact` + 附原文 | 184 | +166 |
| `compact` | 154 | +136 |
| `checklist` | 123 | **+105** |

复现：`node evals/cost.mjs`

## 怎么读这张表

**1. 看绝对增量，不看倍数。** 一句 10 tokens 的话被编译成 266，是 25 倍；一句 83 tokens 的（`long-pasta`）编译成 448，是 5 倍。倍数只反映输入有多短。

**2. 默认档位是最贵的一档。** 附原文（+35）和 `bluf` 的标题（+75）是能用 `--style compact --keep-original off` 省掉的。

**3. 地板在 100–120 tokens。** 再小的请求也压不到这个数以下 —— 那是「目标 / 要求 / 交付 / 完成标准」这套骨架本身的价格，它不会随输入缩小。

**4. 长请求本来就不该被收束。** 用户写了 80 tokens 以上，说明他已经在组织语言了；再包一层，绝对开销最大、边际收益最小。

## 三档做法

```bash
funnel compile "..."                          # 默认：+245
funnel compile "..." --style compact --keep-original off   # +136
funnel compile "..." --budget 150             # 超了自动降级到上面那档，再超会明说
```

`--budget N` 的行为是确定的：先按你给的排版生成；超过 N 就重算一次 `compact` + 不附原文；如果这样仍超，**明确告诉你超了**，并建议直接发原文——而不是悄悄截断。

## 这笔钱值不值

按 DeepSeek 的价格（输入约 ¥1 / 百万 tokens）：

| 用量 | 额外成本 |
| --- | --- |
| 100 条/天 | 约 ¥0.02 / 天 |
| 1000 条/天 | 约 ¥0.25 / 天 |

所以对个人使用，成本基本可以忽略；**真正该在意的不是钱，是延迟和注意力**：

- 编译本身是纯本地规则，**不增加一次模型往返**（API 引擎除外，那是可选的）；
- 提示词变长会占用上下文，长会话里这是实打实的拥挤。

## 什么时候别用

- 单点提问（「这个报错为什么」）——闸门会自己放行，0 开销；
- 已经写得很完整的请求（带约束、带验收）——同样会被放行；
- 长会话的后段——上下文已经紧张时，宁可原样发，或者只用 `compact`。

## 还能怎么省（未实现）

- **跨轮去重**：同一轮对话里，完成标准基本不变，`continue` 仍在重复携带；
- **按引擎决定是否附原文**：规则引擎的输出本来就是用户原话的重排，附原文往往冗余；只有 `api` 引擎（会改写措辞）才真的需要它来自证。这一条大概能省 35 tokens/次，但会削弱「原文优先」的可审计性，所以先没动。
