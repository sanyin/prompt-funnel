# prompt-funnel 设计书（一页版）

> 在请求进入模型之前，把缺的信息显式化：该问的就问，猜的就标出来，编的一律拦掉。

## 问题：不是「不会用 AI」，是「说不清要什么」

「帮我写个爬虫，顺便加个代理池」——模型不会问你要哪个网站、用什么技术栈。它挑一组默认值，给你 3000 字看起来专业、但技术栈是它替你选的实现。

缺的通常是四件事之一：**目标、交付形态、约束、验收**。而模型的默认值会写进回答，下一轮被当成前提——猜测就这样变成了「事实」。

## 定位：不是模板库，也不是 AI 改写器

| 做法 | 问题 |
| --- | --- |
| 模板库（「高质量提示词 100 条」） | 用户还是不知道该填什么 |
| AI 改写器（「让 GPT 帮你写好提示词」） | 编造不可见：分不清哪句是你说的、哪句是它猜的 |
| **本工具** | 只做信息显式化：不替你写内容，只把「缺什么」变成可见、可答、可验证 |

## 三个机制

1. **闸门**——先判断值不值得改。清晰的原样放行（**字节相同**），不打扰是能长期用下去的前提。
2. **来源标注**——每个字段记着 `user / inferred / assumption`，非用户的一律标「假定」。
3. **保真校验**——输出里出现原文没有的数字、路径、URL，直接判 error。不问模型「你有没有编」，问原文。

## 现状与数字（可复现）

| 单元测试 | 离线用例 | 运行时依赖 | tokens 开销 |
| --- | --- | --- | --- |
| **128** | **16/16** | **0** | **+117 ~ +272**（按排版） |

真实模型 A/B（60 次调用）：「明确说出假设」**5/30 → 18/30**，「带自检表述」2/30 → 17/30。**但这是关键词匹配，且模板里本来含这些词，不能读成倍数**——只作方向性证据。

六个入口共用一个内核：网页 / 浏览器扩展 / CLI / MCP / Claude Code 钩子 / Codex·DSH 技能。

## 局限（如实）

- 规则引擎**不理解语义**，靠标记词，中文口语会漏标；漏了不会编造，表现为保留率偏低。
- **没有人工盲评**：只测一个模型、10 个用例，「回答质量更好」目前没有证据。
- 敏感信息靠正则，抓不到自定义格式；浏览器扩展只在本地假页面验证过。

## 想请教的三个问题

1. **评测**：没有预算做大规模盲评时，什么样的评测方式才可信？
2. **定位**：「开发者的工具」还是「普通人的入口」？两者产品形态完全不同，我倾向先选一个。
3. **安全方向**：往「AI 使用安全」走，最该补的是什么？我的判断是 PII 脱敏 + 注入隔离评估 + 威胁模型，而不是提示词改写。
