# 三个真实例子

下面都是实际运行输出，除了去掉终端颜色外未做修改。

---

## 例 1：清晰的提问 —— 不改

```
$ funnel review "为什么这个报错？TypeError: x is not a function"
────────────
闸门
────────────
判定      放行    清晰度 0.66
签名      goal 0.95 · deliverable 0.85 · context 0.30 · constraints 0.15 · acceptance 0.60 · risk 1.00
意图      debug    引擎 rules
说明      闸门判定：已足够清晰，原样放行（加 --force 可强制收束）
理由      加权清晰度 0.66 ≥ 阈值 0.62，原样放行
────────────────────
原文（闸门判定无需收束）
────────────────────
为什么这个报错？TypeError: x is not a function
```

**这里发生了什么**：上报了一个错误信息（`context` 0.30）、问的是具体问题（`goal` 0.95），提问本身就有隐含的完成标准（`acceptance` 0.60）。总分过了 0.62，直接放行。

输出与输入**逐字节相同**——不是「原样 + 一句注释」，测试里有断言。这是能不能长期开着它的关键：如果每条消息都被改一遍，用户会学会无脑按回车。

---

## 例 2：一件事拆成三件 —— 拆开并追问

```
$ funnel compile "帮我写一个爬虫，同时加上代理池，另外再做一个可视化面板"
```

```markdown
## 目标

帮我写一个爬虫

## 要求

1. 加上代理池
2. 再做一个可视化面板

## 交付

- 形式：可运行的改动 + 简短的变更说明（假定）

## 完成标准

- [ ] 逐条对照上面的要求自检，并说明未满足的条目（假定）

## 待确认

_以下条目未确认，按默认假设处理：_

1. 这几件事是一次全做，还是先做第一件？
2. 希望什么形态的交付物？
3. 怎样算做完？（能跑通的命令 / 通过测试 / 字数范围）

**假定**

- 按顺序全部完成，先交付第一件 —— 若不符：范围超出单个回答的容量，后几项会变浅
- 可运行的改动 + 简短的变更说明 —— 若不符：形态不对需要整体返工
- 按上文逐条自检，并说明哪些条目未满足 —— 若不符：无法验收，返工概率上升
- 沿用项目现有技术栈与版本 —— 若不符：环境不符会导致代码不可用

---

## 原文（与上文冲突时以此为准）

帮我写一个爬虫，同时加上代理池，另外再做一个可视化面板
```

**这里发生了什么**

- 三个任务被拆成「目标 + 两条要求」，**没有改写任何措辞**，只做了切分和编号。
- 「爬虫」「代理池」「面板」原样保留；没有补 URL、没有补语言、没有补并发数。
- 三件事放在一轮里会互相稀释，所以问了范围；没答就按「先做第一件」走，并写明后果。
- 原文被附在末尾：模型可以随时回看用户的原始措辞，冲突时以原文为准。

## 例 3：改到你认可为止

```
$ funnel review "帮我优化一下这个东西"
```

```
────────────
闸门
────────────
判定      收束    清晰度 0.44
签名      goal 1.00 · deliverable 0.25 · context 0.00 · constraints 0.15 · acceptance 0.10 · risk 1.00
意图      execute    引擎 rules
理由      没说要交付什么形态
理由      加权清晰度 0.44 低于阈值 0.62，值得先收束
```

```
[回车] 采用并输出  ·  [e] 编辑  ·  [r] 给意见重做  ·  [d] 看差异  ·  [s] 换排版  ·  [q] 退出
> d
```

```
差异：原文 → 收束
- 帮我优化一下这个东西
+ ## 目标
+
+ 帮我优化一下这个东西
+ ...
```

```
> e
```

按 `e` 直接在 `$EDITOR` 里改。改完保存即生效——**不再经过任何模型**，所以不存在「它又把你的修改改回去了」这种事。改完仍会跑一次保真校验，新增的数字/路径会被点名。

```
> 回车
```

接受后：提示词输出到 stdout（可以直接管道给别的程序），同时写入 `.funnel/last.md`，spec 写入 `.funnel/last.json`。想改结构就改 `last.json`，再用 `funnel render` 重新排版——不需要重跑分析。

---

## 注意它们共同的一点

三个例子里，工具**没有一次替用户做决定**。缺的信息要么变成「待确认」，要么变成标了「假定」的默认值并注明后果。这不是措辞上的讲究，而是它能被信任的前提：你随时能看出哪句话是你说的、哪句是它猜的。

为什么这么设计、否决了哪些方案，见 [DESIGN.md](./DESIGN.md)。
